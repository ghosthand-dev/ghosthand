The **ghosthand daemon** serves every CLI command as an HTTP route. The CLI and the MCP
server are thin clients of this API, so anything they do, your code can do too.

```diagram
  your code ──HTTP──>┌──────────────────┐──USB──────────> screenshots, OCR, lock state
  ghosthand CLI ────>│ ghosthand daemon │
  MCP client ───────>└──────────────────┘──Bluetooth────> taps, swipes, keys, typing
```

## Quick start

Every request goes to the **unix socket** at `~/.ghosthand/daemon.sock`. Start the daemon
once with `ghosthand daemon start` (the CLI also starts it by itself).

```bash
SOCK=~/.ghosthand/daemon.sock

# 1. take the iPhone
curl --unix-socket $SOCK http://localhost/v1/leases \
  -H 'content-type: application/json' \
  -d '{"reason":"reply to Anna in Messages","label":"ses_123"}'
# {"id":"42","device":"7EF219AD-...","deviceName":"Tommy's iPhone",...}

# 2. read the screen
curl --unix-socket $SOCK http://localhost/v1/leases/42/text
curl --unix-socket $SOCK -o screen.png http://localhost/v1/leases/42/screenshot

# 3. tap a button by its text, and get the new screen text in the same call
curl --unix-socket $SOCK 'http://localhost/v1/leases/42/tap?screentext=true' \
  -H 'content-type: application/json' -d '{"text":"Messages"}'

# 4. give the iPhone back
curl --unix-socket $SOCK -X DELETE http://localhost/v1/leases/42
```

## Transport and authentication

The daemon always listens on the **unix socket**. Its file permissions allow only your
user, so it needs no token. The host in the URL is ignored; use `http://localhost`.

The HTTP API is **local**. To reach the iPhones from anywhere, connect an agent to the
**remote MCP server** at `https://ghosthand.dev/mcp` (OAuth, same Google account). While the
Mac is signed in, the daemon keeps a WebSocket to ghosthand.dev and MCP calls go through it.

Start the daemon with `--port` to listen on **TCP**, for a client on your network. TCP
requests need a bearer token, and HTTPS needs a certificate:

```bash
GHOSTHAND_TOKEN=secret ghosthand daemon start --port 7420 --host 0.0.0.0 \
  --tls-cert cert.pem --tls-key key.pem

curl https://mac.local:7420/v1/devices -H 'Authorization: Bearer secret'
```

<Aside>
<Warning>
The TCP listener **rejects browser requests** (any `Origin` or `Sec-Fetch-*` header) and
never sends CORS headers. Call it from a server or a native client.
</Warning>
</Aside>

The generated cURL examples on the endpoint pages use TCP. The **Socket** tab shows the
same request over the unix socket, and the **CLI** tab shows the matching `ghosthand`
command.

## Leases

Screen and input routes run on a **lease**, so two agents never drive one iPhone at the
same time. `POST /v1/leases` returns an id; every route under `/v1/leases/{lease}/` then
runs on that iPhone.

```diagram
  POST /v1/leases ──> { "id": "42" }
        │
        v
  /v1/leases/42/screenshot, /text, /tap, /type, ...   (each call resets the idle timer)
        │
        v
  DELETE /v1/leases/42      or 600 s without a call ──> iPhone free for the next client
```

- **One holder.** While a lease holds the iPhone, `POST /v1/leases` fails at once with
  `device-leased`. The detail says who holds it and why, so you can give up or wait.
- **Waiting.** Send `waitSeconds` to retry every second instead of failing.
- **Force.** `force: true` ends the other lease. Use it only when its holder is gone.
- **AssistiveTouch.** Acquire turns it on when it is off. Release turns it off again.

<Aside>
<Info>
Lease ids only increase, also across daemon restarts. A **`label`** is display text,
not a way to resume a lease.
</Info>
</Aside>

## Coordinates

`x` and `y` are **pixels of the screenshot image**. By default images and OCR boxes use
screen points (414x896 on an iPhone XR), so a vision model can send the coordinates it
reads from the image as they are.

Pass `scale=1` on the screenshot and on the input to work in native pixels instead. Use
the same `scale` for reading and for input.

## Read the screen after an input

Input routes take extra **query parameters** that run after the input, on the same lease.
One request then replaces three:

| Parameter    | What it adds                                                        |
| ------------ | ------------------------------------------------------------------- |
| `waitText`   | Waits until an OCR line contains this text (`timeoutMs`, max 60 s). |
| `screenshot` | Returns the still screen as base64 `png` or `jpeg` in `screenshot`. |
| `screentext` | Returns the OCR text of the still screen in `screen`.               |

```bash
curl --unix-socket ~/.ghosthand/daemon.sock \
  'http://localhost/v1/leases/42/tap?waitText=About&screentext=true' \
  -H 'content-type: application/json' -d '{"text":"General"}'
```

<Aside>
<Warning>
An error from these steps (for example **`wait-text-timeout`**) means the input was
sent. Read the screen before you decide what to do. Never repeat the input blindly.
</Warning>
</Aside>

## Progress with server-sent events

An input can wait up to **300 s** while the iPhone pairs or reconnects over Bluetooth.
Send `Accept: text/event-stream` to get progress on the same request:

```bash
curl -N --unix-socket ~/.ghosthand/daemon.sock http://localhost/v1/leases/42/tap \
  -H 'accept: text/event-stream' -H 'content-type: application/json' \
  -d '{"x":207,"y":448}'
```

```text
event: log
data: {"message":"checking Bluetooth device 1A2B3C4D by moving its pointer"}

event: result
data: {"message":"tapped 207,448","logs":["checking Bluetooth device 1A2B3C4D by moving its pointer"]}
```

- The stream ends with **`result`** or **`error`** (a Problem). The HTTP status is always
  200, so read the last event.
- A `: ping` comment line comes every second.
- When you close the connection, the daemon stops the operation before its next Bluetooth
  action. Without the header, a disconnect does not stop it.

## Errors

Errors are always `application/problem+json` ([RFC 9457](https://www.rfc-editor.org/rfc/rfc9457)).
Switch on **`code`**; `detail` tells a person or an agent what to do next.

```json
{
  "code": "device-locked",
  "title": "iPhone locked",
  "status": 409,
  "detail": "Tommy's iPhone is locked. Unlock it before tapping text"
}
```

| Code                     | Status | Meaning                                                     |
| ------------------------ | ------ | ----------------------------------------------------------- |
| `invalid-request`        | 400    | The body or a parameter is wrong. Nothing was sent.         |
| `unauthorized`           | 401    | TCP request without the right bearer token.                 |
| `permission-denied`      | 403    | Browser request, Camera access denied, or remote `executable`. |
| `lease-invalid`          | 403    | The lease is unknown, expired, released or forced away.     |
| `not-found`              | 404    | No such route.                                              |
| `device-not-found`       | 404    | No iPhone matches `device`.                                 |
| `no-device`              | 404    | No trusted iPhone on USB. The detail says what USB sees.    |
| `text-not-found`         | 404    | No OCR line matches the tap `text`.                         |
| `no-recording`           | 404    | Nothing was recorded since the last stop.                   |
| `multiple-devices`       | 409    | Several iPhones are connected; pass `device`.               |
| `device-locked`          | 409    | The iPhone needs its passcode.                              |
| `device-leased`          | 409    | Another lease holds the iPhone.                             |
| `lock-failed`            | 409    | The lock shortcut did not lock the iPhone.                  |
| `unlock-failed`          | 409    | The passcode did not unlock it. It is never retried.        |
| `recording-active`       | 409    | The iPhone is already recording.                            |
| `daemon-busy`            | 409    | Restart with `ifIdle` while a lease is active.              |
| `cancelled`              | 499    | The client closed the stream.                               |
| `internal-error`         | 500    | A bug in the daemon. The detail has the cause.              |
| `recording-failed`       | 500    | The video writer failed, for example a full disk.           |
| `bluetooth-unavailable`  | 503    | Bluetooth is off or not allowed on the Mac.                 |
| `bluetooth-disconnected` | 503    | The Bluetooth link dropped during the input.                |
| `no-frame`               | 503    | USB screen capture sent no frame.                           |
| `pointer-not-found`      | 503    | The AssistiveTouch pointer was not seen on screen.          |
| `lock-state-unavailable` | 503    | The lock state could not be read over USB.                  |
| `lockdown-unavailable`   | 503    | USB lockdown did not answer.                                |
| `mute-unconfirmed`       | 503    | iOS did not confirm the mute state. It never presses again. |
| `pairing-timeout`        | 504    | The iPhone did not pair or reconnect in time.               |
| `wait-text-timeout`      | 504    | The input was sent, but `waitText` did not appear.          |

## OpenAPI document

The daemon serves the exact spec it was built from at `GET /v1/openapi.yaml`. Generate a
typed client from it with any OpenAPI generator. The Swift CLI is built from the same file
with swift-openapi-generator.

```bash
curl --unix-socket ~/.ghosthand/daemon.sock http://localhost/v1/openapi.yaml > ghosthand.yaml
```
